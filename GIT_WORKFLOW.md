# Git workflow

This guide is at the repository root as `GIT_WORKFLOW.md`. Work from the
repository root. The GitHub Actions workflows are in `.github/workflows/`:

- `ci.yml` runs training, tests, and a Docker build on GitHub-hosted runners.
- `lab8_ci.yml` runs the MLOps pipeline for Lab 8.
- `lab9_failure_tests.yml` runs Lab 9's invalid-input and recovery checks.
- `lab12_monitoring.yml` runs breast-cancer drift, performance, and candidate-model checks.
- `lab13_runner_test.yml` checks the self-hosted Windows runner prerequisites.
- `lab13_end_to_end.yml` runs the Lab 13 train-to-Kubernetes integration.

Lab 13 runs on pushes to `main` and on manual dispatch. The self-hosted runner
must be online with the `self-hosted`, `Windows`, and `X64` labels, Python 3.11,
Docker Desktop, and a configured Kubernetes context that can use the locally
built `breast-cancer-api:latest` image.

Before publishing, verify the configured remote and branch:

```powershell
git status --short --branch
git remote -v
```

The raw dataset is deliberately tracked so a fresh clone can train and build the API. Generated model files, logs, metrics, and predictions are ignored or regenerated by the pipeline.

For a focused change, create a branch, review the staged diff, then push and
open a pull request:

```powershell
git switch -c feature/short-description
git add .
git diff --cached
git commit -m "Describe the breast cancer project change"
git push -u origin feature/short-description
```

The branch and pull request trigger the CI workflow. Lab 8 and Lab 9 can also
be started from the GitHub Actions tab with **Run workflow**.

Do not commit real patient data, credentials, generated model artifacts, or
environment files. The included Wisconsin dataset is public demonstration data;
the model is not validated for clinical use.
